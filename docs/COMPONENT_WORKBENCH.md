# Component Workbench

组件实验室现在是应用的默认启动入口。正式记账界面保留为 `PRODUCT PREVIEW`，只用于验证组件装配结果。

```text
Component Workbench（无数据库依赖）
├── Design Tokens
├── Base Components
├── Business Components
├── Page Frames
├── Interaction Tests
└── Product Preview（主动进入后才读取真实业务状态）
```

## 规则

1. 新组件必须先进入实验室，覆盖正常、禁用、空白、加载、错误、长文本和极端数值。
2. 实验室直接调用正式组件，不允许绘制一份仅用于展示的仿制品。
3. 正式页面只能组合经过实验室验证的组件，不得在页面内部重新实现同类控件。
4. 同一种业务对象默认只有一个组件和一个事件接口；确需变体时必须显式命名并共享业务规则。
5. 实验室使用固定假数据，不读取或修改用户账单。

当前已覆盖颜色、字体、间距、圆角、按钮、Surface、金额、状态、长文本、流水条目、流水列表，
以及日历日期格的空白、普通、今天、选中、收支、转账、多币种和极端金额状态。

实验室还包含流水、日历、统计、账户、账单详情、记账编辑、标签系统与迷你数字键盘的大界面草图，
以及收支统计、资产走势、收支对比、支出占比和收支热力五类数据图表。图表使用统一的日／月／年周期选择方式。
长页面只展示草图目录；每张草图都能进入独立的完整手机页面预览。草图不连接数据库；确定方案后再使用
同一批正式组件装配到产品页面。

视觉系统不再只有黑、白、红三色。黑色仍是结构背景，红色仍是品牌强调；收入、支出、资产、转账、
提醒和分类图表分别读取统一语义色。业务页面只能声明信息含义，不能自行写十六进制颜色。

记账编辑草图参考一木的成熟流程重新组织为：收支模式、一级分类、展开的二级分类、账单附加信息与
底部迷你数字键盘。草图中的分类与金额可以交互，但不会写入数据库。
## 单条流水

- 使用统一的 `TransactionListItem`，圆角、背景和边框来自视觉系统。
- 点击后展示点阵涟漪；草稿预览不跳转，用于单独评估触感与视觉效果。
- 产品页面复用同一组件，只替换点击事件的去向。
